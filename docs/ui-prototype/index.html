关于 ZeroChat 的架构设计

帮我分析一下 ZeroChat 项目的架构，有哪些可以改进的地方？

从架构角度来看，ZeroChat 有几个值得改进的方向：

1. 代码组织

当前 Web 端的 App.tsx 文件超过 260KB，包含了所有业务逻辑。建议拆分为：

目录结构 
src/
├── features/chat/       # 聊天功能
├── features/settings/   # 设置页面
├── features/sidebar/    # 侧边栏
├── state/               # 状态管理
├── services/            # 业务服务
└── design-system/       # UI 组件库

2. 状态管理

引入 Zustand 做全局状态，避免 prop drilling 和组件内直接操作 IndexedDB。

3. 流式输出

原生端（Android/iOS/Linux）目前没有流式响应，用户需要等待完整回复。这是体验上的最大短板。
